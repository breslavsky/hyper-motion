# Pure Kinetic Storybook

A live catalogue of all shipped Pure Kinetic components, using Storybook
HTML/Vite and the **HyperFrames 0.9.19 Player**. It runs locally or as a static
site. It is separate from the film storyboard data in `core/storybook`.

Write all Storybook UI and bundled examples in English, including sidebar
names, controls, accessibility labels, errors, and sample text inside the
player. Authors can enter their own copy in any supported language.

## Open the catalogue

From this directory, with Node 22.12 or newer:

```sh
npm ci
npm run dev
```

Open <http://127.0.0.1:6006>. Search or select a component in the sidebar.

By default the catalogue reads `../../kit` in this checkout.
To preview a maintained kit from another worktree, set its absolute template
directory before preparing, testing, building or starting Storybook:

```sh
export PURE_KINETIC_TEMPLATE=/path/to/kit
npm test
npm run build
```

Keep the same variable set for `npm run test:browser` so its expected catalogue
matches the served build. The selected template supplies metadata, controls,
semantic validation, compiler and runtime assets together. Its source files
are read without modification; generated copies live only in this tool's
ignored build directories. Rebuild when changing the selection.

- The toolbar offers **format** (16:9, 9:16 or 1:1), an optional **brandbook**,
  and **3D material** (As in the example, Glass, Dark Glass or Metal). A Glass
  scene's examples **Glass**, **Dark Glass** and **Metal** start on their own material and the
  toolbar switches all of them; elsewhere "As in the example" is Glass. The material applies to the shared
  Liquid Glass components, every scene of the Glass family and the rides made of them.
  Ordinary DOM typography, buttons and cards keep their normal appearance.
- **B-Rolls** holds Glass scenes laid over footage that plays on a track of
  its own (`over`): the scene draws only its glass, and the preview plays a
  sample video under it in step with the scene. They are generated by
  `scripts/prepare.mjs` (`BROLLS`), each small and at the bottom of the frame.
- All Glass examples have a **Background** selector above the player. Pick
  **Photo** or **Video** to try the bundled media, or use **Upload file…**
  for a screenshot, photo or clip from your computer. The selection belongs
  to that example for the current tab. **From recipe** restores the background
  from the component controls. For an export, copy your file to the project's
  `assets/` folder and use the relative path shown in **Component recipe**.
  The photo sample shows the Great Bahama Bank on February 15, 2020. Image by
  Joshua Stevens, NASA Earth Observatory, using USGS Landsat 8 data. [Image source](https://science.nasa.gov/earth/earth-observatory/still-sandy-after-all-these-years-146697/)
- The initial brandbook selection is **Default**: native component colours
  and typography, with no brand font, colour tokens or logo overrides. The
  recipe retains only the Nook sample name and URL required by the catalogue.
- The selected brandbook supplies the name, URL, font and all four colour
  roles together. Changing material preserves this brand, the component's
  layout and its animation. Old font, look, colour-preset and Metal-variant
  URL settings are ignored.
- **Controls** edits the actual component fields and its duration in beats.
  The field descriptions show the existing content limits. Brand colours and
  typography are selected through the brandbook instead of individual fields.
- In **Pure Kinetic / glass / ask / On the beat**, open **Controls → Timing**.
  `bpm` sets the film tempo, `beats` sets the scene length, and `speed`
  changes the component's motion. The keys in `timing` place individual
  actions on beats relative to the scene start. In this example, changing
  `send` from 3 to 3.5 moves the press and its exported click from 1.50 s
  to 1.75 s at 120 BPM.
- The native player provides play, pause, scrubbing and speed. Reduced-motion
  users get a paused, readable frame instead of automatic playback.
- **Docs** contains the component description and its parameter table. Only
  the most visible example mounts a player; offscreen examples stay lightweight.
  Scrolling releases the previous player and restores its position and manual
  pause state when it returns. Hiding the browser tab suspends playback too.
- Named examples appear beneath components whose canonical metadata opts in
  to enum variants. Thinking Orbs has one example for each of its nine states,
  alongside the general editable preview.
- **Pure Kinetic / glass** includes the Three.js `glass-island`, `glass-controls`, `glass-ask`, `glass-lens`,
  `glass-search` and `glass-send-prompt` components. In `glass-search`, edit
  `query` to change the text typed into the field. The search button shows
  a spinner from the `timing.search` beat. The field begins folding into
  the button at `timing.collapse`. At `timing.collapsed` only the button
  and its spinner remain. At `timing.checked` the spinner becomes a
  checkmark and holds. In `glass-send-prompt`, the
  camera tracks the typing caret and pulls back in an arc to reveal the glass
  composer. Its optional `chips` label the topics or sources of the request
  above the prompt. Set `chips` to `[]` to hide this row. The `pull` and
  `landed` timing controls pin the camera move to the music. In **Send wave**, clicking the round Send button replays the distortion wave up the composer.
  Set `timing.send` to the beat of the click and `timing.sent` to the beat
  when the surface settles.
  Island exposes static/orbit camera examples and
  hold/collapse exits. Ask, Controls and Lens expose static/orbit examples.
  Ask types the editable prompt and reveals its optional reply on the projected
  glass surface. Controls
  keeps its switch sequence and optional slider fill on one projected panel.
  The three materials share control colours. The active switch and slider use
  green or the selected brand accent. The slider's round thumb carries an
  insert in the same colour. The unfilled portion of its track is neutral grey.
  The card has a 16-unit inset and 12 units between rows. Single-line switch
  rows are 32 units tall, with their centres 44 units apart. The slider label
  sits 4 units above the thumb box. The track spans the same left and right
  guides as the switch rows.
  The optical Island, Controls and Ask cards share typography, padding, gaps,
  responsive width and minimum height. Text fits automatically on the same
  type scale and stays top-aligned; Island's optional Lucide icon adds a
  leading slot beside the title. These are the production card layouts.
  Glass, Dark Glass and Metal use these same factories, layouts and camera paths. The
  material selector changes the surface finish while preserving the selected
  brandbook. No separate legacy renderer is selected for the Metal examples.
  Metal uses the original Libraries.dev/Paper shader: a thin animated chromatic
  rim, a quiet centre and a soft halo. Each world shares one fixed-size shader
  texture across its cards; the native timeline drives both rim and halo.
  The finish follows the same capsule/card morphs. Metal surfaces are opaque
  across cards, lenses and controls. Dark Glass adds a smoky tint to the
  refracted background. Select **Glass → controls → Dark Glass** for the
  switch and slider example. Glass traces every panel as a thick slab with a
  fully rounded edge; it shows best over a photo or a video background.
  The kit documents the shared spacing, camera and material rules in its
  [optical glass component guide](../../kit/source/lib/components/README.md#optical-glass).
  In the Lens and Send-prompt previews, lettering stays sharp as the lens
  or wave crosses the frame. To check a change at preview and export
  resolution, follow the [Glass text sharpness checks](../../kit/source/lib/components/README.md#text-sharpness).
- Material comparisons use the shared 3D Liquid Glass components. Copy,
  brandbook and aspect remain editable. The material selector does not apply
  the finish to ordinary DOM text or UI surfaces.
- **Component recipe** exposes the resulting `film.json` for reuse in a film.

Component stories preview visuals. Their production soundtrack is generated when
the recipe is published; changing text here does not play an outdated audio
mix. Image fields accept existing relative assets. The catalogue does not import
media from users' projects; brandbook fonts can refer to existing assets in the
selected template.

## Brandbooks

The bundled toolbar offers **Default** plus **49 demonstration brandbooks**.
The default option restores native component colours and font without selecting
a book. It also applies when the brandbook setting is absent or empty. The
sample name and URL remain Nook / nook.app; they do not impose visual overrides.
Three explicit
entries in `brandbooks.json` — **Indigo · demo**, **Lime · demo** and
**Warm · demo** — preserve the catalogue's existing palettes, each with the
Nook sample identity and Geist font. Indigo retains the `nook` key so existing
brandbook URLs keep working.

Preparation also derives 46 books from the selected kit's 44 canonical themes:
each theme supplies its colours and font, with Metal represented by Silver,
Gold and Chromatic palettes. These use the same Nook sample identity. The
canonical compiler selects the background, readable text and primary accent;
the second accent comes from the same theme's palette. No separate palette
copy is maintained for these derived books. Selecting one changes colours
and font; material, component geometry and animation remain independent.

Each configured entry has a label and one production `brand` object; for
example:

```json
{
  "acme": {
    "label": "Acme",
    "brand": {
      "name": "Acme",
      "url": "acme.example",
      "font": "Geist",
      "tokens": {
        "background": "#f5f5fb",
        "foreground": "#181830",
        "accent": "#6554ef",
        "accent2": "#ffa4ca"
      }
    }
  }
}
```

For configured brandbooks, the font and all four colour roles are required and
checked against the production recipe validator. **Default** remains the
initial selection independently of the order of these entries.
Custom font files and optional logos must already exist in the selected kit's
`source/assets`; preparation copies those referenced assets into the catalogue.
Use a bundled font name, or a production `{family, src, weight?}` font object
whose local file exists under the selected template's `source/assets/`.
Preparation copies that font into the preview assets.
Use an external file to replace the entire bundled map, including derived
theme books, without editing this tool. The **Default** option remains
available alongside that external map:

```sh
export PURE_KINETIC_BRANDBOOKS=/absolute/path/to/brandbooks.json
npm test
npm run build
```

Keep this setting for development and browser tests, and rebuild after changing
the file. Preparation copies the validated map into the generated catalogue.
Every generated recipe receives its own copy of the selected `brand` object.

## See scenes connected

Open **Pure Kinetic → Sequences → idea-to-action → From Idea to Action**.
The 13.61-second example connects a title, typing, an expanding card and an end
card with glide, open and circle transitions. Play it as one film or use the four
scene buttons to pause on a readable frame. The toolbar changes the format;
font, look and brand are fixed for this authored example and their toolbar
controls are locked. The full recipe appears below the player.

`examples/idea-to-action.json` owns the example. Preparation validates it and
calls the production compiler and native project builder for each format.
The three HTML roots share the existing kit and native scene definitions.
HyperFrames owns every scene clock; the production presentation owns the
transitions. As in the component stories, the preview omits the mixed audio.
This is an example of sequential scenes, not the separate Document Flow world
or a visual timeline editor.

## See one continuous world

Open **Pure Kinetic → Sequences → folio → Folio — Continuous Story**.
The 17.78-second example follows six persistent documents through Collect,
Arrange and Create with one shared camera. Click **Play with sound** to
start from the beginning with music and 26 event sounds. It initially shows a
paused, muted frame so audio starts from a deliberate browser gesture.
The five phase buttons pause on readable moments; the native player supplies
scrubbing, volume, playback speed and looping. All three formats are available.

This story uses the production Document Flow builder and canonical
`document-flow/examples/folio.json`. Its authored Folio brand and Geist Mono
font are fixed; component look/brand presets do not apply. One shared asset
directory serves all three formats. Audio follows the same compiled event plan
as the world, through native HyperFrames tracks. No separate preview audio
clock or mixer is added. The complete world recipe appears below the player.

## Build and verify

```sh
npm test
npm run build
npm run preview
```

In a second terminal:

```sh
npm run test:browser
npm run test:browser -- --all
npm run test:browser -- --metal
npm run test:sequences
npm run test:folio
npm run test:browser -- --glass
node tests/ask-optics.mjs
node tests/glass-backgrounds.mjs
```

None of this runs in CI. `kit/tools/test.sh storybook`
builds the Storybook, serves it and runs all of the above in one go.

`CHROME_BIN` can select a Chrome executable. `STORYBOOK_URL` selects another
origin, including a static build served below a URL prefix. The short browser
suite covers representative components in all three formats, including
typing, drag/scan, registry components, Canvas and WebGL. `--all` checks all
component/format combinations. Both modes check every named enum variant in
all three formats. With Orbs installed, this includes nine state stories,
independent player clocks, reverse Canvas pixels and a full Storybook shell
screenshot with the state examples visible. It also checks real Controls and toolbar
updates, complete brandbook application, validation/recovery and lifecycle.
Reports and representative screenshots are written under `test-results/`.
The browser command also runs both focused sequence suites. The scene suite checks
all three formats, real transition overlaps, forward/backward seeking, scene
buttons, playback and format-change cleanup. It also opens the full Storybook
manager to verify that scene buttons remain visible and ordinary component
Controls still work after leaving the example.
The Folio suite checks persistent object identity and one camera through all
five phases in three formats, forward/backward seeking, source and audio-plan
integrity, decoded sound assets and real native audio output after a trusted
click, including mute, pause, playback speed and disposal. Its test-only analyser
observes the native output without replacing the audio graph or player clock.
The Folio manager checks also exercise the real format toolbar, visible phase
and sound buttons, locked authored styling, and restoration of ordinary
component Controls and brand selections after leaving Folio.
On failure, diagnostics and a screenshot capture the live iframe before cleanup,
including failed or pending asset requests and native-player readiness.

`preview` uses the installed Vite server, as does CI. Choose another port with
`npm run preview -- --port 6008`; use the matching `STORYBOOK_URL` for browser
tests. The static output can also be served by an ordinary production web server.

`--metal` runs the focused 3D material suite in three formats: native seeking,
different material pixels, toolbar changes and cleanup when returning to Glass.
It checks that the brandbook, compiled motion, camera, geometry and projected
text stay the same between materials, that stale toolbar settings cannot
override a brandbook, and captures the real Storybook sidebar.
The regular short and full suites include these material checks too.

`--glass` runs the Liquid Glass components and their canonical named
variants in every format. It verifies native clock and reverse-seek pixels,
projected editable text, the Lens text texture, Controls changes, and independent
player cleanup. It records frames before/after the glass crossing and a real
Storybook shell screenshot. These glass integration checks also join the
regular short/full suite.

`tests/ask-optics.mjs` measures the phase of transmitted stripes as the reply
panel grows. It checks that the existing upper face, its reflection and the
backdrop stay fixed and that resizing the player preserves the rendered frame.

## Source of truth

`prepare:catalog` reads the existing catalogue, field schemas, samples,
descriptions and limits. It generates ordinary CSF stories; it does not keep a
second component list. Missing examples or schema entries fail preparation.

Adding an imported component includes adding it here: supply its canonical
catalogue entry, field schema, guide and sample, then prepare and run the
model and browser checks. To expose meaningful modes as named examples, add
`previewVariants: ['state']` (or the component's actual enum field names) to
its canonical metadata. Stories derive their values from those enum fields;
do not duplicate the values or hand-edit generated stories. Invalid enum
references and colliding story names fail preparation. New modes inherit
Controls, brandbook/material/format options and reusable recipes automatically.

Imported effects are ready for use when their editable preview and meaningful
variants render through the native player and survive seeking, not merely
when their names appear in the sidebar. Effects that have only been researched
are added after their working adapter and canonical sample exist.

The browser preview compiles a single-scene recipe with the production plan
compiler and mounts the production component. Playback and seeking belong to
the pinned HyperFrames runtime/player. There are no custom scene clocks or
private HyperFrames imports.

`public/`, `generated/`, `storybook-static/` and `test-results/` are ignored build
outputs. The asset copy in `public/` is regenerated from the kit, never edited
as a separate source. `npm run dev` and `npm run build` regenerate it; restart
dev after changing the underlying component kit or its metadata.

Storybook, Vite and browser-test dependencies live only in this tooling package.
They are not installed into films or the production harness runtime. CI runs
its short browser suite when this catalogue or the component source changes.
